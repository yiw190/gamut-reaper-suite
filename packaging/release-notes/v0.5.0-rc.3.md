**Release candidate 3: security and speed.** Everything from rc.2 plus an audit pass: the installer, the HTTP
front, the gateway and the release pipeline are tightened, and the panel, bridge and gateway do less work per frame
and per request.

### Install
1. **REAPER first** — [reaper.fm](https://www.reaper.fm/download.php). Both installers refuse to continue without it.
2. **Hibiki** — macOS: `Hibiki-0.5.0-rc.3.pkg`; Windows (10 1803+, 64-bit): `Hibiki-0.5.0-rc.3-setup.exe` (per user, no
   admin rights). Not signed yet: macOS → Privacy & Security → **Open Anyway**; Windows SmartScreen → **More info → Run
   anyway**.
3. **Restart REAPER** — the panel opens docked on the right.

### Security
- **macOS installer**: the root postinstall no longer creates, writes or `chown`s anything in your home folder (a
  symlinked log file could have been turned into a root write). `hibiki setup` runs as you and writes its own
  `~/Library/Logs/hibiki-install.log`; `/var/log/hibiki-install.log` only records the exit code.
- **MCP bearer**: the HTTP front refuses to start with a bearer under 32 characters. `hibiki setup` replaces a short
  one (and updates the Gamut registration) and `scripts/macos-host-bootstrap.sh` generates one with a CSPRNG
  when none is given.
- **Gateway**: Origin / Host / token are checked from the headers before any body is read (an unauthenticated client
  could make it read 50 MB); at most 32 requests and 64 streams in flight, then 503; 60 s read timeout. Agent slugs,
  session ids and Gamut agent ids from requests must match `[A-Za-z0-9._-]+`.
- **Windows terminal lines** (login, "Open in …"): values with `"` or line breaks are refused instead of silently
  stripped, `%` is doubled so cmd can't expand it, env names are checked. The panel validates ids and quoting the same
  way before it builds a command.
- **Panel**: its temp files live in a private folder, and the auth file it passes to `curl` is written 0600.
- **ACP agents**: `hibiki agents add` installs each adapter at a pinned version (codex-acp 2.2.2, claude-agent-acp
  0.94.0, kimi-code 2.3.0, MiniMax code 0.6.12, grok 1.0.67) with install scripts off. MiniMax keeps them: its SQLite
  binding and ripgrep are fetched by them.
- **Supply chain**: the remote-host bootstrap installs cloudflared 2026.10.3 and checks its sha256 instead of
  `releases/latest`. CI: read-only `GITHUB_TOKEN` by default (the release job alone may write), every action pinned
  to a commit, Inno Setup pinned to 6.7.1.
- `scripts/deploy_bridge.py -T` warns that it puts the bearer in `ps`; use `REAPER_MCP_BEARER`.
- README: put a Cloudflare Access policy in front of a tunnelled MCP; the bearer shouldn't be the only gate.

### Faster
- **Bridge JSON**: strings without anything to escape are copied whole and string decoding copies runs instead of
  single bytes. A 10,000-note MIDI payload (1.2 MB) encodes in 40 ms instead of 92 ms and decodes in 49 ms instead of
  101 ms. Output is byte-for-byte the same as before, invalid UTF-8 included.
- **Panel**:
  - Replies are laid out incrementally while they stream instead of re-parsing the whole markdown every frame.
  - Messages off screen are skipped.
  - Fewer background `curl`s, and `pkill` runs off the UI thread.
  - The MIDI selection pill is cached.
  - SSE parsing is linear.
  - The transcript refreshes with `?after=<last id>` and only fetches new messages.
- **Gateway**: `GET …/sessions/<id>/messages?after=<msgId>` returns `{"after", "messages"}` (only newer messages) for
  ACP and Gamut chats, or `{"full": true, "messages"}` when the id is unknown. Without `after` it's the plain array as
  before.
- **Gateway, idle agents**: `/status?probe=1` no longer starts every ACP agent; it checks the binary and returns the
  last-known login state. `probe=<slug>` starts that one agent. An agent with no turn running and no open stream for
  10 minutes is stopped together with the MCP servers it launched, and restarts on the next message.
- **MCP HTTP front**: `initialize`, `tools/list` and `ping` are answered without waiting behind a long render. Replies
  are matched to requests by id, so a notification can't shift every later answer by one. A hung server process is
  restarted after a timeout: 30 s for quick calls, 600 s plus the render budget for tool calls.

### New
- **`hibiki recover`** and the panel's **Recover** button: restarts the MCP front and the gateway (their agents go
  with them), kills stuck panel stream `curl`s, puts back a missing bridge script / panel / token, waits for both
  services and reports the REAPER bridge heartbeat. It never kills REAPER. `--json` for scripts.

### Upgrading
Install the new package over rc.2, rc.1 or v0.4.1. A bearer shorter than 32 characters is replaced on upgrade and the Gamut
registration is updated with it (Claude and Cursor use stdio and don't need one). Tunnel clients with a hand-copied bearer
need the new value from `~/.config/reaper-mcp/token`.
