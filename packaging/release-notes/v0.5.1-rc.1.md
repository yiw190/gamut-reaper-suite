**Release candidate 1 for 0.5.1: stop/start, updates from the panel, and a dev mode for testing unreleased code.** Everything from v0.5.0, plus the changes below.

### Install
Install `Hibiki-0.5.1-rc.1.pkg` (macOS) or `Hibiki-0.5.1-rc.1-setup.exe` (Windows) over v0.5.0, then restart REAPER so the new bridge and panel load. `hibiki doctor` should show `0.5.1-rc.1`. Installing a package always switches the machine back to that release (see `hibiki use` below).

### New
- **`hibiki stop` / `hibiki start`**:
  - `stop` turns off the MCP service, the agent gateway, the watchdog and the Cloudflare tunnel (if it's installed). They stay off after login until you run `start` or `setup`.
  - `start` brings back only what was running before. `doctor` reports stopped services as "stopped", not as failures.
  - While stopped, Recover won't turn them back on; it tells you to run `hibiki start`.
  - On Windows, `stop` ends the supervisor and removes the logon autostart.
- **Updates**:
  - `hibiki update [--check] [--install] [--channel stable|dev]` checks GitHub releases. `--install` downloads the package, verifies its sha256 and opens the installer for you to finish. It never installs silently and never uses sudo.
  - Agent settings has a new **Hibiki** box: your version, **Check for updates**, **Install**, and an "Include dev builds" switch.
  - It checks on its own when you open settings, at most once a day, and never installs automatically.
- **`hibiki use dev | release | status`**:
  - Runs a local git checkout (default `~/reaper-mcp`) with the package's own Python, for testing unreleased code.
  - It switches the services, the REAPER scripts and the MCP registrations, and every `hibiki` command (including the panel's Recover and update) forwards to the checkout. `use release` switches back.
  - Installing a package clears dev mode.
  - `doctor`'s first line shows the current mode and commit.
- **Panel profiler**: set ExtState `Hibiki/profile` to `1` and per-section frame times appear in `Hibiki/prof`. It costs nothing while off.

### Changed
- **Long chats stay light.** The panel draws only the last 60 messages; scroll to the top or click **Load earlier messages** to load more.
  - 3,000 messages now take 377 ImGui calls per frame instead of 7,724.
  - Measured on an M4 with a very long chat: 5.7 ms per frame before, 4.1 ms after.
- **Chat titles follow Gamut's renames.** After Gamut renames a chat, the header and the recent-chats list update.
- **Recent chats use the LED bar** instead of `●`: blue while a chat is running, grey otherwise.
- **Tool line**: the line under a reply shows the per-tool counts (`>_ Bash ×7`); the extra "N calls" total is gone.
- **Agent settings** opens at the top, flush against the left edge of the chat panel.
- **No console window when REAPER starts**: the bridge no longer prints "ready" to the ReaScript console. Errors still show up there, and `REAPER_MCP_DEBUG=1` brings the startup line back.

### Fixed
- A gateway test that failed now and then with a stray 503 on slow CI runners.

### Not yet
- Signing and notarization of the installers.
- `render stems=true` can still produce the master instead of stems; use `solo_indices` renders until it's fixed.

### Upgrading
Install over v0.5.0. If you were in dev mode, the installer switches you back to this release.
